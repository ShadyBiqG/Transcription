# Transcription Next

Это самостоятельное приложение-кандидат для локальной транскрибации. Оно не
импортирует legacy-сервис, noScribe или его данные. По умолчанию приложение
слушает `127.0.0.1:8010` и хранит SQLite в собственном каталоге `./data`.

На данном этапе реализованы изолированная конфигурация, SQLite, саморегистрация
по e-mail или логину и паролю, cookie-сессии, CSRF и RBAC; private jobs, API редакторских
ревизий, общий каталог голосовых профилей и интерфейс с аудиоплеером и
синхронными субтитрами. Реальная обработка запускается только после проверки
локальных model packs. Windows-установщик доставляет закреплённый набор моделей
и FFmpeg с проверкой SHA-256 и локальным smoke-check; во время работы
приложение ничего не скачивает. Явно добавленный владельцем образец превращается в
защищённый WAV и через durable outbox попадает в новое immutable-поколение
общего ZeusDB-индекса. Новые записи могут получить автоматическое назначение
только после отдельной калибровки порогов; иначе группа остаётся неизвестной
либо показывается для ручной проверки.

## Работа в интерфейсе

До входа пользователь выбирает один из двух режимов: **Войти** или
**Зарегистрироваться**. После успешного входа формы авторизации скрываются, а
доступно только рабочее пространство текущей учётной записи.

Добавление записи и запуск обработки — два намеренно разных действия:

1. Нажмите **Загрузить запись**, выберите локальный `.webm` и подтвердите
   **Добавить в список**. Файл станет личной записью со статусом `uploaded`;
   обработка на этом шаге не запускается.
2. В карточке этой записи нажмите **Транскрибировать**. Только это действие
   создаёт запуск в локальной очереди. Повторное нажатие во время активного
   запуска не создаёт вторую обработку.

Администратор не получает доступ к чужим файлам, текстам, аудио или карточкам
заданий. В разделе администрирования он видит только агрегированную статистику
записей по пользователям и может назначать либо снимать роль администратора;
последнего активного администратора нельзя понизить или отключить.

### Контракт административного API

`GET /api/v1/admin/users` доступен только администратору и возвращает учётные
записи вместе с `statistics`: общим количеством записей и счётчиками каждого
статуса. В ответ намеренно не входят идентификаторы заданий, имена или пути
файлов, аудио, текст транскрипции, ошибки обработки и голосовые метки.

`PATCH /api/v1/admin/users/{user_id}` с CSRF-заголовком принимает
`{"role":"admin"}` или `{"role":"user"}`. Саморегистрация никогда не
принимает роль из запроса и всегда создаёт обычного пользователя.

`GET /api/v1/jobs` возвращает только задания текущего владельца. Ответ содержит
`items` и `next_cursor`; `current_run` включает только статус, этап, попытку и
безопасный код ошибки. Новая страница запрашивается параметрами `limit` и
`cursor`. `POST /api/v1/jobs/{job_id}/runs` принимает запись в очередь только
при готовом ASR-пакете и работающем worker.

`GET /api/v1/jobs/{job_id}/vocabulary/suggestions?expected_revision_number=N`
возвращает проверяемые предложения терминов для текущей ревизии. Предложение не
меняет текст: пользователь применяет его в редакторе и явно сохраняет новую
ревизию. Чужое задание отвечает `404`.

`/health` — liveness-проверка SQLite. `/ready` дополнительно требует
работающий worker и проверенные локальные model packs; поэтому при остановленном
или деградировавшем worker он возвращает `503`.

## Запуск

Требуются Python 3.12 и `uv`. Без переменных окружения используются отдельные
значения кандидата: `./data` и `127.0.0.1:8010`.

```powershell
uv sync --dev
uv run local-voice-transcriber
```

После запуска доступны `http://127.0.0.1:8010/health` и интерактивная документация
`http://127.0.0.1:8010/docs`. API находится под `/api/v1`.

Первого администратора создаёт оператор сервера, а не публичная регистрация:

```powershell
uv run local-voice-transcriber --create-admin admin@example.test
```

Пароль будет запрошен без передачи в командной строке. Файл `.env.example`
содержит только необязательные параметры окружения и не должен попадать в Git.

## Установка на Windows Server

Скрипт `deploy/install-windows.ps1` создаёт отдельный data root, локальное
окружение, модели и FFmpeg, проверяет их локальную загрузку, а затем при первой
установке интерактивно создаёт первого администратора. Пароль не записывается в
конфигурационный файл. Git-установщик после этого автоматически регистрирует
автозапускаемую службу Windows `TranscriptionNextCandidateService`. Legacy на
порту 8000 не изменяется. Подробнее:
`deploy/README.md`.

Если на сервере ещё нет исходного кода, скопируйте туда один файл
`deploy/install-from-git.bat` и выполните его из `cmd.exe`. Он сам клонирует
указанную ветку, затем запускает PowerShell-установщик:

```bat
install-from-git.bat "<URL Git-репозитория>" "C:\Services\TranscriptionNext" "E:\TranscriptionData" "<опубликованная-ветка-кандидата>"
```

Для обновления этого же чистого клона добавьте `--update`. Скрипт допускает
только `git pull --ff-only`, сверяет URL `origin` и активную ветку, поэтому не
перезаписывает другой репозиторий или локальные правки.

Состав автоматически доставляемых и проверяемых ASR/VAD/voice model packs:
[docs/model-packs.md](docs/model-packs.md).

Запускайте Git-установщик из PowerShell **от имени администратора**: тогда он
сам зарегистрирует и запустит отдельную автозапускаемую Windows-службу
`TranscriptionNextCandidateService`. Она не изменяет legacy-службу.

## Безопасность и изоляция

- `NEXT_DATA_DIR` должен быть отдельным каталогом candidate; путь базы не может
  выходить за его пределы.
- Пользовательская регистрация всегда создаёт только роль `user`. Адрес e-mail
  допускается как логин; отдельное поле `email` и роль от клиента не принимаются.
- Сессия находится исключительно в `HttpOnly` cookie
  `local_voice_transcriber_session`. CSRF-токен в отдельной cookie должен быть
  передан в заголовке `X-CSRF-Token` для запросов, изменяющих состояние.
- Администратор управляет только учётными записями и техническими данными. Доступа
  к будущему чужому содержимому заданий эта роль не даёт.
- Общий voice index обслуживается ровно одним процессом приложения для одного
  `NEXT_DATA_DIR`. Не запускайте два экземпляра или несколько Uvicorn workers с
  одним data root: installer уже запускает безопасный однопроцессный вариант.

Не добавляйте `.env`, каталог `data/`, SQLite, журналы или реальные записи в Git.

## Проверка

```powershell
uv run ruff check .
uv run pytest
```

Чтобы не прогонять один и тот же полный набор после каждой небольшой правки,
используйте целевой набор из `scripts/test-candidate.ps1`:

```powershell
# HTML, CSS и JavaScript
.\scripts\test-candidate.ps1 -Suite ui

# Очередь, запуск, recovery и owner-scoped jobs
.\scripts\test-candidate.ps1 -Suite jobs

# Редактор, ревизии и словарные предложения
.\scripts\test-candidate.ps1 -Suite editor

# Сессии, CSRF и роли
.\scripts\test-candidate.ps1 -Suite auth

# Один раз перед push или выпуском
.\scripts\test-candidate.ps1 -Suite full
```

Загрузка реальных ASR/VAD/Sherpa-пакетов и FFmpeg остаётся отдельным smoke-test
установщика. Запускайте его при изменении моделей, зависимостей или deployment,
а не после обычной правки интерфейса.
