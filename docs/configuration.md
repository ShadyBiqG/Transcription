# Настройка сервиса и файла `.env`

Этот документ описывает все параметры текущей версии сервиса. Для Windows-службы файл конфигурации должен находиться здесь:

```text
C:\Services\Transcription\.env
```

Сервис читает `.env` при запуске. После любого изменения перезапустите службу:

```powershell
Set-Location 'C:\Services\Transcription\deploy\windows-service'
.\TranscriptionService.exe restart
.\TranscriptionService.exe status
```

Не добавляйте `.env` в Git: в нём находятся настройки конкретного сервера. Файл уже исключён через `.gitignore`. Пример без секретов хранится в `.env.example`.

Если одна и та же переменная уже задана в окружении процесса Windows, она имеет приоритет над значением из `.env`. Для предсказуемой настройки службы рекомендуется хранить параметры приложения в одном `.env`, а в XML оставлять только параметры кодировки и команду запуска.

## Рекомендуемый `.env` для текущего сервера

```dotenv
TRANSCRIPTION_DATA_DIR=E:\TranscriptionData
TRANSCRIPTION_NOSCRIBE_PATH=C:\Program Files (x86)\noScribe\noScribe.exe
TRANSCRIPTION_DEFAULT_LANGUAGE=ru
TRANSCRIPTION_DEFAULT_MODEL=precise
TRANSCRIPTION_ALLOWED_MODELS=fast,precise
TRANSCRIPTION_MAX_UPLOAD_BYTES=5368709120
TRANSCRIPTION_NOSCRIBE_TIMEOUT_SECONDS=21600
TRANSCRIPTION_SESSION_TTL_DAYS=30
TRANSCRIPTION_COOKIE_SECURE=false
```

В значениях Windows-путей не нужны кавычки, даже если путь содержит пробелы. Обратные слеши записываются как обычно и не требуют удвоения в реальном `.env`:

```dotenv
TRANSCRIPTION_NOSCRIBE_PATH=C:\Program Files (x86)\noScribe\noScribe.exe
```

## `TRANSCRIPTION_DATA_DIR`

Каталог постоянных данных приложения.

```dotenv
TRANSCRIPTION_DATA_DIR=E:\TranscriptionData
```

В нём создаются:

```text
E:\TranscriptionData\jobs.sqlite3       пользователи, сессии и задания
E:\TranscriptionData\jobs\<job-id>\    записи и результаты
E:\TranscriptionData\tmp\               незавершённые загрузки
```

Если значение относительное, например `./data`, путь считается от текущего рабочего каталога. У комплектной Windows-службы это `C:\Services\Transcription`, поэтому `./data` станет `C:\Services\Transcription\data`.

Для сервера рекомендуется абсолютный путь `E:\TranscriptionData`. Учётной записи Windows-службы нужны права на создание, чтение, изменение и удаление файлов в этом каталоге. Подключённые пользователем сетевые диски с буквами использовать не следует: служба может их не видеть.

Значение по умолчанию: `./data`.

## `TRANSCRIPTION_NOSCRIBE_PATH`

Полный путь к установленному `noScribe.exe` на сервере.

```dotenv
TRANSCRIPTION_NOSCRIBE_PATH=C:\Program Files (x86)\noScribe\noScribe.exe
```

Программа должна быть установлена на той же машине, где запущена служба. При старте сервис выполняет `noScribe.exe --help-models`. Если файл отсутствует, не запускается или не сообщает ни одной разрешённой модели, health вернёт `noscribe: unavailable`, а новые задания приниматься не будут.

Значение по умолчанию: `C:\Program Files (x86)\noScribe\noScribe.exe`.

Проверка вручную под учётной записью службы:

```powershell
& 'C:\Program Files (x86)\noScribe\noScribe.exe' --help-models
```

## `TRANSCRIPTION_DEFAULT_LANGUAGE`

Язык, заранее выбранный в форме нового задания.

```dotenv
TRANSCRIPTION_DEFAULT_LANGUAGE=ru
```

Допускается `auto` либо код из 2–8 латинских букв. Например: `ru`, `en`, `de`. Пользователь может изменить значение перед загрузкой конкретной записи.

Значение по умолчанию: `ru`.

## `TRANSCRIPTION_DEFAULT_MODEL`

Модель noScribe, заранее выбранная в форме.

```dotenv
TRANSCRIPTION_DEFAULT_MODEL=precise
```

Значение обязательно должно присутствовать в `TRANSCRIPTION_ALLOWED_MODELS`. Если это условие нарушено, сервис завершится при старте с ошибкой конфигурации.

Обычно:

- `precise` — более точная, но более долгая обработка;
- `fast` — более быстрая обработка с возможным снижением точности.

Значение по умолчанию: `precise`.

## `TRANSCRIPTION_ALLOWED_MODELS`

Список моделей, которые сервис разрешает выбрать и передать noScribe.

```dotenv
TRANSCRIPTION_ALLOWED_MODELS=fast,precise
```

Значения разделяются запятыми. Пробелы вокруг названий удаляются. Пустые элементы игнорируются. Это не устанавливает модели: они должны быть заранее загружены в noScribe под той же учётной записью Windows, от которой запускается служба.

При старте сервис пересекает этот список с результатом `noScribe.exe --help-models`. В веб-интерфейсе health показывает реально найденные модели.

Значение по умолчанию: `fast,precise`.

## `TRANSCRIPTION_MAX_UPLOAD_BYTES`

Максимальный размер одного загружаемого `.webm` в байтах.

```dotenv
TRANSCRIPTION_MAX_UPLOAD_BYTES=5368709120
```

`5368709120` байт — 5 ГиБ. Другие примеры:

| Лимит | Значение |
|---|---:|
| 500 МиБ | `524288000` |
| 1 ГиБ | `1073741824` |
| 2 ГиБ | `2147483648` |
| 5 ГиБ | `5368709120` |

Файл поступает частями и записывается во временный каталог. Если лимит превышен, загрузка прекращается, временные данные удаляются, а задание не создаётся. Значение должно быть целым числом больше нуля.

Значение по умолчанию: 5 ГиБ.

## `TRANSCRIPTION_NOSCRIBE_TIMEOUT_SECONDS`

Максимальное время работы noScribe для одного задания в секундах.

```dotenv
TRANSCRIPTION_NOSCRIBE_TIMEOUT_SECONDS=21600
```

`21600` секунд — 6 часов. Таймаут начинает учитываться после запуска noScribe и не включает время передачи файла с компьютера пользователя. При превышении процесс завершается, а задание получает ошибку `noscribe_timeout`.

Значение должно быть целым числом больше нуля. Для длинных записей и медленного CPU его можно увеличить.

Значение по умолчанию: 21600 секунд.

## `TRANSCRIPTION_SESSION_TTL_DAYS`

Срок действия новой пользовательской сессии в днях.

```dotenv
TRANSCRIPTION_SESSION_TTL_DAYS=30
```

После регистрации или входа браузер получает случайную `HttpOnly` cookie, а база хранит только SHA-256-хеш её значения. По истечении срока пользователь должен войти снова. Изменение параметра действует на новые сессии; уже созданные сохраняют прежнюю дату окончания.

Значение должно быть целым числом больше нуля.

Значение по умолчанию: 30 дней.

## `TRANSCRIPTION_COOKIE_SECURE`

Управляет флагом `Secure` пользовательской cookie.

Для текущего прямого доступа по HTTP:

```dotenv
TRANSCRIPTION_COOKIE_SECURE=false
```

После настройки HTTPS:

```dotenv
TRANSCRIPTION_COOKIE_SECURE=true
```

При `true` браузер отправляет cookie только по HTTPS. Если включить этот параметр при открытии `http://<IP-СЕРВЕРА>:8000`, регистрация может пройти, но следующий запрос снова покажет страницу входа.

Как `true` распознаются значения `1`, `true`, `yes`, `on` без учёта регистра. Любое другое значение считается `false`.

Cookie также всегда получает флаги `HttpOnly` и `SameSite=Lax`. `HttpOnly` закрывает доступ к токену из JavaScript, а `SameSite=Lax` ограничивает его отправку с посторонних сайтов.

Значение по умолчанию: `false`.

## Определение говорящих и внешний провайдер

`TRANSCRIPTION_FFMPEG_PATH` задаёт полный путь к `ffmpeg.exe`. Если значение пустое,
сервис ищет FFmpeg в `PATH`, затем в комплекте установленного noScribe.

`TRANSCRIPTION_EXTERNAL_API_BASE_URL` по умолчанию равен `https://routerai.ru/api/v1`.
Таймаут задаётся `TRANSCRIPTION_EXTERNAL_API_TIMEOUT_SECONDS`, число полных кадров на
реплику — `TRANSCRIPTION_ATTRIBUTION_MAX_FRAMES` (от 1 до 5,
по умолчанию 2). Кадры берутся вблизи середины реплики, а не у её границ.

Перед запуском пользователь выбирает режим определения. `Быстрый` анализирует
репрезентативные реплики каждой уникальной метки `S00/S01` и переносит имя на все
реплики этой метки. `Точный` анализирует каждую реплику отдельно, поэтому работает
дольше и создаёт больше внешних вызовов. Режим по умолчанию — `Быстрый`.

Название и URL любого OpenAI-compatible провайдера можно изменить в админке.
Сервис пытается получить стандартный `/models`; при ошибке модели вводятся вручную.
API-ключ не хранится в `.env`: администратор вводит его в веб-интерфейсе, после чего
ключ шифруется Windows DPAPI для учётной записи службы. В интерфейсе отображается
только маска. Сервис пытается загрузить каталог моделей выбранного провайдера;
если `/models` недоступен, разрешённый список, основная и резервная модели вводятся
вручную. Все параметры и лимиты сохраняются в SQLite.

Кнопка «Проверить модель и ключ» выполняет реальный пробный vision-запрос к основной
модели, а не только проверяет существование ключа. В разделе статистики сохраняются
HTTP-код и сообщение провайдера, показывается понятная категория причины и исходный
текст ошибки. Это позволяет отличить неверный ключ (401/403), нехватку баланса (402),
ограничение частоты (429), временную ошибку провайдера (5xx), отсутствие vision-входа
и несовместимость `response_format/json_schema`.

Если модель возвращает невосстановимую ошибку совместимости, сервис один раз
переключается на резервную и больше не вызывает проблемную модель в этом запуске.
Временные ошибки 429 и 5xx не отключают модель до конца запуска. Введённая вручную
модель не может быть заранее проверена по каталогу, поэтому перед большой обработкой
обязательно выполните «Проверить модель и ключ».

Рекомендуемый профиль, доступный в каталогах RouterAI и Polza.ai:

| Назначение | Идентификатор | Почему выбран |
|---|---|---|
| Основная | `google/gemini-2.5-flash-lite` | Недорогая мультимодальная модель; подтверждена успешными vision-вызовами через Polza.ai. |
| Резервная | `deepseek/deepseek-v4.1-flash` | Vision-модель другого семейства; дешевле Gemini 3.1 и может работать через совместимый JSON-режим. |

На 11 сентября 2026 года каталоги указывают для основной модели примерно 11–12 ₽
за 1 млн входных и 44–47 ₽ за 1 млн выходных токенов. В реальной истории Polza.ai
один вызов с тремя кадрами стоил около 0,013 ₽. Цены динамические: перед эксплуатацией
обновите каталог в админке. `qwen/qwen3.8-27b` и модели Mistral не следует добавлять
в рабочий профиль Polza.ai без успешного пробного vision-запроса: наличие модели и
модальности `image` в каталоге само по себе не гарантирует совместимость конкретного
endpoint со строгой JSON-схемой.

Модели, которые принимают изображения и поддерживают только `response_format`, также
показываются в совместимом каталоге. Сервис сначала запрашивает строгий
`json_schema`, а при явном HTTP 400 о неподдерживаемой схеме повторяет неоплаченный
запрос в режиме `json_object` и самостоятельно проверяет все поля результата. Это
позволяет тестировать `deepseek/deepseek-v4.1-flash` через Polza.ai и те endpoint'ы
RouterAI, где строгий structured output недоступен.

Для Polza.ai сервис также читает вложенные `top_provider.supported_parameters` и
`top_provider.pricing`, а стоимость завершённого вызова берёт из `usage.cost_rub`,
если провайдер возвращает её непосредственно в ответе.
Цена и идентификатор генерации сохраняются даже тогда, когда провайдер успешно
выполнил и тарифицировал запрос, но приложение не смогло разобрать ответ модели.
Для дополнительного получения цены поддерживается Polza.ai endpoint
`/history/generations/{id}` наряду с RouterAI `/generation?id=...`.

Лимит ответа рассчитывается по числу кадров (850 токенов для одного, 1350 для трёх),
чтобы JSON с результатами не обрезался на прежней границе 500 токенов. Если только
один из нескольких кадров содержит уверенно прочитанную подпись, а остальные ей не
противоречат, подпись принимается; конфликтующие или неуверенные результаты остаются
`unknown`.

Первого администратора создайте до запуска службы от той же Windows-учётной записи:

```powershell
uv run transcription-service --create-admin admin@example.com
```

Адрес и порт задаются аргументами команды:

```powershell
uv run transcription-service --host 0.0.0.0 --port 8000
```

| Аргумент | По умолчанию | Назначение |
|---|---|---|
| `--host` | `127.0.0.1` | `127.0.0.1` разрешает доступ только с сервера; `0.0.0.0` — через все его сетевые интерфейсы. |
| `--port` | `8000` | TCP-порт веб-сервиса. Он должен совпадать с правилом Windows Firewall. |
| `--reload` | выключен | Автоперезапуск при изменении кода; только для разработки, не для Windows-службы. |
| `--create-admin EMAIL` | — | Интерактивно создаёт администратора или повышает существующего пользователя. |

Комплектный `TranscriptionService.xml` уже запускает `--host 0.0.0.0 --port 8000`.

## Переменные кодировки Windows-службы

В `deploy\windows-service\TranscriptionService.xml` дополнительно заданы:

```xml
<env name="PYTHONUTF8" value="1" />
<env name="PYTHONIOENCODING" value="utf-8" />
```

Они нужны для корректного вывода кириллицы. Сам noScribe запускается через Windows ConPTY, потому что упакованная версия noScribe может игнорировать обычное перенаправление кодировки. Удалять эти строки не следует.

## Проверка применённой конфигурации

После перезапуска службы:

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/api/v1/health'
```

Ожидаемый результат:

```text
service  : ok
noscribe : ready
models   : {fast, precise}
worker   : running
```

Проверка каталога данных:

```powershell
Get-Item 'E:\TranscriptionData'
Get-Item 'E:\TranscriptionData\jobs.sqlite3'
```

Проверка сетевого порта:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8000
```

Если после изменения `.env` служба не запускается, проверьте журналы `C:\Services\Transcription\deploy\windows-service\logs`. Нечисловое значение лимита или таймаута, нулевой срок сессии либо модель по умолчанию вне разрешённого списка приводят к отказу запуска — это защищает сервис от работы с неоднозначной конфигурацией.

## Безопасность текущей версии

- Подтверждения почты и восстановления пароля пока нет.
- Любой человек, которому доступен сервис по сети, может зарегистрировать учётную запись.
- Email приводится к нижнему регистру; повторная регистрация того же адреса запрещена.
- Пароль должен содержать от 8 до 128 символов.
- Пользователь видит только собственные новые задания.
- Пароли хранятся как `scrypt`-хеши; исходные пароли восстановить из базы нельзя.
- Обычный HTTP не шифрует пароль, cookie и записи. Используйте его только в доверенной локальной сети/VPN. Для доступа через недоверенные сети сначала настройте HTTPS.
- Не публикуйте порт 8000 напрямую в интернет.
